# InfoRisk 产品需求文档

> 文档维护：DingJiaye  
> 最近更新：2026-08-31  
> 本文定义产品体验、视觉与交互要求；页面业务字段、接口及数据口径以现有服务实现为准。

## 1. 产品定位

InfoRisk 是面向银行风险管理人员的信息系统与风险预测智能体。它持续汇集公开信息、主体事件、评级与行业资料，将来源、风险判断及可执行关注事项沉淀为可复核的情报任务流。

产品体验应体现为 **Risk Intelligence Command Center（风险情报作战驾驶舱）**，而非传统的管理后台：

- AI Agent 是主动发现、核验与解释风险的核心；
- 用户可通过导航进入新闻汇总、主体评估、行业分析、国际评级，也可通过全局指令直接提问；
- 信息层级、时间线、状态及证据链优先于大量独立卡片；
- 所有 AI 结论必须保留来源、时间和人工复核入口。

## 2. 信息架构与核心交互

### 2.1 全局结构

顶部保留四个主入口：`新闻汇总`、`主体评估`、`行业分析`、`国际评级`。顶部同时提供全局 Command Bar：

```text
⌘ 询问 InfoRisk…
示例：分析 Godiva 最近 30 天的风险变化
```

用户提交问题后，Agent 应优先回答，并在需要时跳转或定位到对应主体、新闻、评级或报告；不得只返回无上下文的聊天文本。

### 2.2 新闻汇总

- 以中东日报、大型企业、宏观市场三个板块为一级信息层级；每个板块使用独立的非告警识别色；
- 各板块内部按发布时间倒序呈现，标题、内容详情、来源、风险标签与风险提示保持明确层次；
- 仅在 AI 判断为“关注”或“风险”时显示对应灯号和文字标签；普通新闻不展示风险灯号；
- 顶部 Agent 监测条显示真实数据：新事件数、需关注事件数、监测信源数，以及“发现 n 条需关注事件”；不重复显示同一统计；
- 支持关键词、日期、板块、风险状态筛选，并支持手工添加新闻和来源 URL。

### 2.3 主体评估

主体页应以“`{主体名称} Risk Intelligence`”为核心标题。右侧或侧栏显示 Agent 的任务状态，而不是只输出长段摘要：

```text
正在分析 Godiva Japan
✓ 企业主体识别
✓ 新闻检索
✓ 财务信息交叉验证
✓ 供应链风险扫描
◉ 融资风险评估
○ 人工复核
```

- “近三个月公开信息事件”按公司/关联方分类，不沿用新闻汇总的三个板块；
- 主体总体等级随新闻状态动态变化：存在风险新闻则为“风险”；无风险但存在关注新闻则为“关注”；其余为“中性”；
- 事件卡中展示“关注”或“风险”灯号及文字标签，避免只在顶部统计中出现；
- 支持关键词、时间、事件类别与风险状态筛选；支持手工新增主体新闻、来源与风险等级。

### 2.4 主动情报

非侵入式的 Agent 提示放在右下角或页面右侧，避免伪装为客服聊天气泡。仅在出现值得关注的新变化时展示，例如：

```text
● InfoRisk Agent
发现 2 个值得关注的变化
⚠ Godiva Japan：融资期限延长
⚠ Sumitomo：澳大利亚资产交易出现变化
[查看风险变化]
```

提示关闭后在当前会话内不重复打扰；用户可从 Agent 面板重新查看。

## 3. 视觉风格

### 3.1 设计语言

- 深色基底，采用深海军蓝、蓝黑与低饱和蓝色光效；
- 主界面为玻璃拟态数据面板：半透明深色表面、细微霓虹描边、克制的标题光泽；
- 视觉目标接近情报终端、现代 SOC 与金融监测平台，强调精确、秩序、可靠，而非游戏化炫技；
- 减少白色 Card、厚阴影、大圆角和无意义留白。内容以页面标题、分隔线、表格、时间线和状态层级组织；
- 容器圆角：大容器 `12px`，小组件 `6px–8px`，数据表格尽量使用直线与细边框；
- 阴影只用于浮层、弹窗和可操作的悬浮对象；常规内容优先使用 `1px` 边框区分层级。

### 3.2 背景与空间

- 背景包含低对比度、持续缓慢移动的火焰光带与粒子光点；底部使用科技网格地面，形成作战驾驶舱纵深；
- 火焰光带仅作为环境氛围，不得使用高饱和红黄，也不得与风险状态绑定；推荐使用蓝紫、青蓝、低饱和琥珀的柔和渐变；
- 数据面板可采用轻微透视与玻璃折射效果，但文本、表格与控件必须保持高对比、清晰可读；
- 仪表盘图标可使用轻微的 Y 轴向内旋转透视效果，角度控制在 `2deg–6deg`，不得影响点击区域和可读性。

### 3.3 色彩语义

| 用途 | 建议色系 | 说明 |
| --- | --- | --- |
| 普通内容、机构识别 | 青蓝、深蓝、紫灰、灰白 | 不表达风险等级，例如穆迪/标普/惠誉来源识别。 |
| 关注 | 低饱和金色/琥珀色 | 仅用于 AI 判断为“关注”的事件。 |
| 风险 | 克制红色 | 仅用于 AI 判断为“风险”的事件。 |
| 正常/在线 | 低饱和绿色 | 仅表示运行正常、已完成、在线。 |
| 装饰光效 | 青蓝、蓝紫、低饱和琥珀 | 不能与关注或风险标签混淆。 |

风险颜色必须始终带文字，例如“关注”“风险”，不能仅凭颜色传达结论。普通新闻不显示黄/红风险标记。

### 3.4 数据组件

作战总览可组合使用以下组件，并以真实数据驱动：

- 指标带：新事件、需关注、重点主体、风险事件；
- 环形进度图：采集、主体识别、风险推演、人工复核完成度；
- 热力地图：地域/国别风险分布；
- 折线实时数据流：事件量、市场指标或风险趋势；
- 条形优先级看板：待核验事件和处理优先级；
- 风险告警日历：按日期展示关注与风险事件；
- 风险矩阵：横轴为发生概率，纵轴为影响程度，映射重点主体。

图表标题、图例与数值不得重叠；仅在数据维度适合时展示图表，避免为了装饰而加入图表。

## 4. 动效与交互规范

### 4.1 静默空闲状态（Idle）

- 所有界面使用低速、持续且克制的缓动；可通过正弦曲线实现元素 `1px–4px` 的上下浮动；
- 面板光晕采用 `3.5s ease-in-out infinite` 的呼吸明暗变化；
- 图表曲线和数据点可平滑过渡更新，不应闪烁、跳变或频繁重绘；
- 背景火焰流光与粒子保持缓慢位移，禁止剧烈闪动、快速旋转或干扰正文阅读；
- 非关键背景动效的透明度与速度必须低于关键状态、风险与用户操作反馈。

### 4.2 点击与视图切换

- 任意面板切换使用 Tween 补间动画，统一缓动函数：`cubic-bezier(0.22, 1, 0.36, 1)`；
- 面板展开/收缩：宽高、位置和透明度插值，默认时长 `320ms`；
- Tab 切换：旧内容淡出，新内容向上 `8px–12px` 淡入，交叉过渡，不得出现整页白屏；
- 卡片/表格行悬浮：上浮 `2px–4px`、边框亮度轻微增强；不改变布局尺寸；
- Command Bar 打开：遮罩 `opacity` 渐入，指令面板 `transform: translateY(8px) scale(.98)` 进入；键盘 Enter 提交、Esc 关闭；
- 长耗时 Agent 操作采用阶段进度（采集、识别、核验、分析）与流式结果，而不是锁定整个页面。

### 4.3 告警动效

- 关注和风险事件可使用低频呼吸灯；普通事件不使用呼吸灯；
- 关注：低亮度金色呼吸，周期不短于 `2.4s`；风险：低亮度红色呼吸，周期不短于 `1.8s`；
- 告警动画只作用于标签/状态点，禁止整张卡片持续闪烁；
- 当页面存在多个风险事件时，优先使用排序、标签和摘要说明，不叠加更多闪烁效果。

## 5. 性能与无障碍约束

- 所有动画必须优先使用 `transform` 与 `opacity`，避免连续修改 `width`、`height`、`top`、`left` 造成布局抖动；
- 使用 `requestAnimationFrame` 或 CSS Animation，避免高频 `setInterval` 触发重排；
- 背景粒子、网格和光带需独立分层，使用 `will-change: transform` 时仅限少量活动元素；
- 首屏优先加载文本、核心指标与最近事件；图表、地图和装饰效果延迟加载；
- 当系统检测到低性能设备、后台页面或 `prefers-reduced-motion: reduce` 时，关闭粒子、持续浮动和非必要过渡；
- 所有状态不得只依赖颜色，必须配合文字、图标、标题或 ARIA 标签；
- 对比度满足 WCAG AA；玻璃拟态背景下正文文字仍应清晰可读。

## 6. 验收标准

1. 用户进入任一核心页面后，可在无需等待全量 AI 任务完成的情况下查看已缓存的信息并继续操作。
2. Agent 任务进度有明确阶段，失败时给出可理解的原因和重试入口。
3. 新闻、主体事件与风险标签的颜色语义一致；机构评级来源色不得被误读为风险色。
4. 页面切换、筛选、展开收缩、弹窗均使用统一动画节奏，且无明显卡顿或布局跳动。
5. `prefers-reduced-motion` 下核心功能完整可用，非必要动效被禁用或显著减弱。
6. 所有图表可读、图例不重叠，并由真实数据驱动。
